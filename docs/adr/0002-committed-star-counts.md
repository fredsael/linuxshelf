# Star counts are committed, refreshed by --stars

A Program's Star count is stored in the program YAML (`stars:`) and refreshed by `scripts/auto-fill.ts --stars`, which makes one request per catalogued repository and always overwrites existing values — unlike release lists, a star count has no hand-curated content to protect. Counts are never fetched at site build time or in the visitor's browser. Committing keeps builds offline-safe and spares visitors GitHub's ~60 requests/hour unauthenticated per-IP limit, at the cost of visible staleness between refresh runs.

The field is host-agnostic: the count comes from the catalogued repository's own platform, currently GitHub (`stargazers_count`), with other platforms' star metrics populating the same field when support is added. A count must always attach to a catalogued repository; a repository swap invalidates the old count, which the next `--stars` run regenerates. Programs with no repository, or no obtainable count, display no Stars cell at all — a dash invites the "zero stars" misreading for e.g. GitLab-hosted projects. The page shows the count abbreviated (`★ 46.1k`) and linked to the repository, and excludes it from the Pagefind index so volatile numbers stay out of the search corpus.
